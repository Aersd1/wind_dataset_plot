# 新容量表与图形说明

历史方案说明；当前七图入口和服务器步骤以 [publication_figures.md](publication_figures.md) 为准。

## 容量及设备字段

容量来自作者提供的 `windfarm_metadata.xlsx` 中机组数量与额定功率：

`风场额定功率 (MW) = Σ(该型号机组数量 × 单机额定功率 kW) / 1000`。

例如 CULLRGWF = (7×2050 + 6×2000 + 2×2050)/1000 = 30.45 MW。
其叶轮直径有两种：82 m 对应 8 台，92.5 m 对应 7 台。不同型号但相同尺寸的机组数量相加。
这是一份按所提供工作簿重算的表，不是独立的厂商参数核验。

清理后的 CSV 删除角色、周边地貌和 Notes，保留来源、位置及气候字段；风机型号、容量、叶轮直径、叶片长、轮毂高分别列出。
三个尺寸字段各有“规格数”和“各规格机组数”列。原表近似值保留 ≈；未提供的尺寸保持为空，不由叶轮直径反推叶片长度。

工作簿共有 132 条，原分析清单为 131 条，额外一条是 huaneng。
完整导出 `windfarm_metadata_clean.csv` 保留 132 条；默认时序配置及图形使用原 131 条，未擅自增加分析对象。
新旧表有 14 个风场容量变化，见容量核对表。

NREL WTK 的 85 条记录描述虚拟机组：容量使用虚拟机组数量 × 2 MW。
文字中列出的若干转子/叶片尺寸属于拟合参考机型，不能解释为每个风场实际安装了这些型号。
CSV 明确标注参数性质、参考机型数，并将此类尺寸的台数注明“参考机型，未分配机组数”。
原表三个 GRGBW 子场站的机组数量带近似符号，相应总容量也标记为近似。

## 已生成的新图

1. `rated_capacity_distribution`：横轴为风场额定容量（MW，对数坐标），纵轴为容量不超过横轴值的风场比例。两组分别从 0% 累计到 100%，因此不会因为陆上风场更多而直接抬高曲线。用于看容量跨度及两组规模构成。
2. `turbine_geometry_diversity`：三列分别为叶轮直径、叶片长、轮毂高。紫色圆点为海上，橙色三角形为陆上。每个风场的已知尺寸分别画点，同一场站有多种尺寸时用横线连接。纵向错开仅为避免遮挡。该图显示 46 个实际机组场站中有记录的尺寸；不混入 NREL 参考机型。
3. `virtual_reference_geometry`：分别展示 NREL 四种功率曲线类别所对应的参考转子尺寸、参考叶片长及配置轮毂高。它说明模拟配置覆盖的设备参数，不是实际机组尺寸分布。
4. `prediction_error_by_updated_groups`：根据新容量对现有零样本 MSE 重新分组。左边比较海上/陆上，右边比较三个容量组；横轴为 16、32、48、64 步预测。点为单个测试风场，箱体为组内第 25–75 百分位，箱内横线为中位数，须为 1.5 倍四分位距内的数据范围，所有风场点均显示。使用实际测试结果，不重新训练模型。

各图不带图名、样本数或底部说明行，导出 PDF、SVG 和 600 dpi PNG；图注放在论文中。

## 原图保留及 f 的替换方案

本版不复制旧图中的数值，而是在新容量下重算：

- 原 b：保留小提琴加散点的形式。每个风场先计算小时平均出力除以额定容量，再展示风场间分布。每个点一个风场；小提琴的宽度表示该水平风场较集中，横线是风场均值的组内中位数。点与轮廓使用同一个统计单位。
- 原 d：保留日/周 STL 强度箱线图。0 表示相应周期不明显，越接近 1 表示该周期在所分析连续序列中越突出。只比较同时有日、周有效统计的风场；24 h 和 168 h 为独立分解，不将周强度解释为去除日周期后的剩余强度。
- 原 e：保留每日曲线的 UMAP 分布。每个点是某风场一个完整 UTC 日的 24 个小时出力比例；颜色为原始 24 维曲线上聚类得到的组。默认沿用 16 组，但实际可分组数以数据为准。相邻点有相似的日出力形状及水平；坐标本身没有功率单位，组号不是物理类别。
- 新 f：用一张“风场 × 一天 24 小时”的热图替代 16 个小曲线。每行一个风场，按整体平均出力排序；每列一个 UTC 小时；颜色是该时刻跨完整日平均的出力占额定容量百分比。读图可直接比较哪些场站全天偏高、哪些时段相对偏高。它显示平均日内轮廓，不展示逐日波动，也不是当地太阳时。
- 上一版 e：仅作为可选中位出力图重算。中位出力就是有一半小时低于它、另一半高于它。它与原 b 信息接近，可在最终排版时二选一，避免重复。

完整日必须来自同一连续片段的 24 个完整小时；每小时取完整原始采样的平均功率。
同一原始风场的所有 aligned_segments 归为同一风场，data_process 层不混入。时间缺口及片段边界不计算相邻变化，不插值补齐。

## fig9_additional.pdf 的含义和波动图

原 PDF 左边纵轴写的是 MSE，因此它比较的是预测误差，而非原始功率的波动。
容量分组依据作者提供的边界：小于 50 MW、50–150 MW（含两端）、大于 150 MW；这是整个风场的额定容量，不是单台风机功率。
原 PDF 本身只写 Small/Medium/Large，未直接印出数值边界；本版将边界明确写入图例。
海上/陆上是部署类型，容量组是规模分类，两种分组回答不同问题。
原 PDF 右边比较零样本到少样本适配后的性能变化，颜色所表示的也是模型性能改善或变差。

新增 `volatility_by_capacity_and_site_type` 专门比较实际发电波动，定义为：

`平均逐小时绝对变化 = mean(|P(t+1) − P(t)| / 风场额定容量) × 100`。

单位为百分点（pp）：例如相邻小时出力由容量的 30% 变到 35%，该次变化为 5 pp。
先对每个风场计算一个值，再分别按三个容量组及海上/陆上画点和箱线，值越大表示逐小时变化越强。
不能用现有 MSE 的高低代替这个指标。不同容量组的来源构成不同，组间结果为描述性比较，不能据此断言容量导致波动变化。

## 服务器运行

在项目根目录安装并检查清单：

```sh
python -m pip install -e .
python -m wind_dataset_plot.revised --config revised_config.json --inspect
```

检查应显示 131 个原始风场、1770 个 aligned_segments、无基于观测最大值的容量替代。
`--inspect` 不读取功率序列。

正式计算：

```sh
python -m wind_dataset_plot.revised --config revised_config.json
```

输入 CSV 的 power 是瞬时 MW，默认采样间隔 15 min，时间戳按 UTC 解释。若源数据使用其他时区，需在配置中明确填写，不能直接套用 UTC。
输入清单保留原服务器路径；若挂载目录不同，用 `inputs.path_prefix_map` 将旧前缀映射到新前缀。
输出写入 `results/revised_capacity`，已有输出不会自动覆盖。`--overwrite` 为显式覆盖选项。
全部符合条件的完整日参与聚类和 UMAP；因此正式运行所需时间和内存取决于保留数据规模。
`--skip-umap` 可显式跳过 UMAP，运行记录会标明缺少该图，不会生成替代图。

输出包括六张图的 PDF/SVG/PNG、逐风场指标、日曲线索引和数值、热图行顺序、容量组来源构成、检查表及输入容量表的 SHA256。
这些时序图必须在服务器实际执行后才能作为更新后的研究结果使用。

元数据图重绘（可选）：

```sh
python -m pip install -r requirements-qa.txt
python tools/plot_metadata.py --tables inputs/revised_metadata --output results/metadata_figures --qa-dir tools/figure_qa --results /path/to/plot_data.csv
```

`plot_data.csv` 为原始实验结果文件；它仅供 MSE 图使用，不是原始功率时序。
